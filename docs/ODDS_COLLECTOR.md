# BKliz: разовая диагностика букмекеров Selenium через GitHub Actions

## Что проверяет пилот

Скрипт `scripts/odds_collector.py` запускает анонимный Chrome в GitHub Actions. Он НЕ извлекает коэффициенты и не делает реальные ставки. Все строки содержат `odds: null`, `market_verified: false`, `price_verified: false`, `start_at_verified: false`. Успех загрузки главной страницы НЕ подтверждает конкретный матч или рынок.

После скриншота с текстом «Доступ заблокирован системой защиты» для «Лиги Ставок» её тестовый матч отключён в `data/odds/targets.json` (`enabled: false`). Новых запросов к этому сайту сборщик не делает, пока пользователь явно не разрешит возобновить тест.

Для PARI, Winline и BetBoom добавлены однократные проверки (по одной обычной загрузке главной страницы):
- `https://pari.ru/` — PARI
- `https://winline.ru/` — Winline
- `https://betboom.ru/` — BetBoom

Это **только тест доступности главной страницы**. Он не доказывает, что открывается линия КХЛ и доступны рыночные котировки.

## Запуск и чтение результатов

1. Откройте https://github.com/StLisovafk13/BKliz/actions/workflows/odds-collector.yml
2. Нажмите `Run workflow → main`, либо дождитесь запланированного запуска в 43-ю минуту часа UTC (минуты ЕКБ и МСК совпадают).
3. Откройте запуск `collect → Probe bookmaker sites once` и посмотрите диагностические статусы трёх сайтов.
4. Внизу страницы запуска в `Artifacts → odds-pilot-...` скачайте ZIP. Внутри `data/odds/latest.json` и скриншоты `odds-diagnostics/*.png`, если изображения удалось получить.
5. Текущая машина Ubuntu/Chrome может получить отказ из-за политики сайта. Данные блокировки сохраняются как `blocked`, а не как «коэффициентов нет».

**Состояния:** `homepage_visible` — видимая страница бренда, но не линия; `homepage_not_verified` — идентичность сайта не установлена; `blocked` — обнаружена CAPTCHA/текст блокировки; `redirected` — переход на другой домен; `empty_page` — нет достаточного содержимого; `source_error` — ошибка Selenium; `paused` — источник отключён; `expired` — тестовый матч уже начался; `event_not_verified` — команды не подтверждены; `event_visible` — команды видны, рынок всё ещё не подтверждён.

## Ограничение на повторы

У каждой главной страницы `one_shot: true` и номер `revision`. После одной завершённой попытки (включая блокировку или ошибку) следующий час не делает новых сетевых обращений. Результат предыдущей проверки хранит исходный `checked_at`; он НЕ считается повторно проверенным.

Если действительно необходим новый тест конкретного сайта, сначала оцените допустимость доступа и вручную увеличьте `revision` у этой цели в `data/odds/targets.json`. Не выполняйте автоматических повторов и не пытайтесь обходить блокировки.

Workflow использует минимально необходимый доступ для записи `data/odds/latest.json`; страницы открываются анонимно без cookies, аккаунтов или авторизации. Скриншоты добавляются только в артефакты запуска, не в публичный сайт. HTML страницы, заголовки запросов, IP пользователя и cookies не сохраняются в исходники. При ошибке проверки workflow показывает ошибку в итоговом статусе, а JSON остаётся диагностическим.

## Что НЕ происходит

- Нет извлечения подтверждённого коэффициента, расчёта EV, изменения условного банка или реальных ставок.
- Нет изменений `data/feeds/cycle.json`, `data/feeds/overview.json`, `data/feeds/signals.json`, старых архивов и сайта.
- Нет утверждения, что успешный GitHub Actions `pages.yml` означает успешный Selenium-тест.

## Проверка кода

```bash
python -m unittest discover -s tests -p test_odds_collector.py -v
python scripts/odds_collector.py
```

Сборщик зависит от Selenium только при фактическом запуске браузера. Для облака `selenium>=4.20,<5` устанавливается существующим workflow.

Если тесты сайтов покажут доступность, отдельным следующим этапом следует реализовать валидатор событий, рынков и реальных коэффициентов; до этого `odds` всегда `null`.
