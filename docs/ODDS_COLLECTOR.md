# BKliz Odds Collector: Selenium-диагностика в GitHub Actions

## Назначение

Технический пилот без VPS и букмекерского API. Облачный Selenium Chrome открывает заранее указанную страницу «Лиги Ставок» на временном GitHub-hosted runner. Компьютер пользователя может быть выключен. Цель пилота: определить, что реально отображается на странице, и проверить присутствие названий участников. Это ещё НЕ чтение точного рынка или подтверждение цены.

В текущем конфиге проверяется «Амур — Салават Юлаев» (17.10.2026 10:00 МСК). Цель перестанет проверяться после указанного времени и получит статус expired. Для следующих проверок нужно добавить будущую встречу с проверенной прямой ссылкой в data/odds/targets.json. Расписание не подбирает матчи самостоятельно.

## Безопасность и точность

- Для каждого наблюдения odds=null, start_at_verified=false, market_verified=false, price_verified=false. Это диагностическая запись, а не проверенный коэффициент, даже при event_visible.
- Скрипт запускает анонимный браузер без профиля, авторизации, подмены cookies и обхода CAPTCHA. При ограничении доступа фиксируется ошибка.
- Скриншот страницы на разрешённом домене сохраняется исключительно как диагностический артефакт GitHub Actions с retention 7 дней; в публичные файлы сайта он не коммитится. На ином домене скриншот не делается.
- В публикуемый JSON входят фактический URL без параметров и фрагмента, короткий заголовок страницы, число видимых символов, признаки видимости команд и имя файла скриншота. Полный HTML, cookies и текст страницы туда не попадают.
- Браузер может видеть другой язык, баннер или список матчей, а не конкретную линию. В data/odds/targets.json допускается добавить team_aliases (по два массива вариантов названий), только после ручной проверки соответствия. Совпадение имён не подтверждает время и тотал.
- Если хотя бы один активный матч не обнаружен или источник недоступен, шаг Probe возвращает ошибку после сохранения JSON, а GitHub Actions отмечает запуск неуспешным. Это нормальный диагностический сигнал.

## Изменённые файлы

- scripts/odds_collector.py — ожидание видимых команд до 22 секунд, классификация, URL/title, анонимный скриншот.
- .github/workflows/odds-collector.yml — ручной старт и cron `43 * * * *` UTC, в артефакт попадают JSON и PNG.
- tests/test_odds_collector.py — проверка групп алиасов, чистого URL, ошибок, просрочки и недопустимости ложных коэффициентов.
- data/odds/targets.json — точный тестовый матч (не изменён), data/odds/latest.json — результат последнего запуска.

## Как получить диагностический скриншот

1. Откройте https://github.com/StLisovafk13/BKliz/actions/workflows/odds-collector.yml
2. Выберите **Run workflow → main → Run workflow**.
3. Откройте выполненный запуск. В `collect` найдите этап **Probe approved bookmaker event**: там будут landing_url, page_title, visible_characters, teams_visible и статус.
4. Ниже на странице запуска в разделе **Artifacts** скачайте ZIP `odds-pilot-...`. Внутри будет `latest.json` и (если Selenium открыл разрешённый домен и смог сделать снимок) `odds-diagnostics/<id>.png`.
5. Если страница выглядит как список событий, ошибка доступа, пустой шаблон или рекламная заглушка, по снимку станет ясно, какой следующий шаг оправдан. Если видно нужный матч и конкретный рынок, можно проектировать отдельный строго проверяемый адаптер цены.

Критерии: `event_visible` означает, что имена обоих участников отображены где-то на странице, но время/рынок/цена не проверены. `event_not_verified` — хотя бы одного имени не видно после ожидания; `blocked` — вероятная защитная страница; `redirected` — браузер покинул допустимый домен; `empty_page` — мало отображённого текста; `source_error` — Selenium не смог завершить проверку; `expired` — время начала наступило.

## Работа с BKliz

data/odds/latest.json — отдельное наблюдение. Не подменяйте им data/feeds/cycle.json и не считайте поисковые результаты действующими ценами. Текущая аналитическая задача ChatGPT может читать диагностический статус, но НЕ должна рассчитывать EV, банк, K0 или финансовый результат из этого файла.

Сборщик не меняет ранее созданные архивы, `data/feeds/overview.json`, `data/feeds/signals.json`, workflow публикации Pages и Telegram. Плановый GitHub Actions работает независимо от компьютера, но может запускаться поздно или не выполниться. Коммит через штатный GITHUB_TOKEN не гарантирует запуск другого workflow от push.

## Локальные проверки

```bash
python -m unittest discover -s tests -p test_odds_collector.py -v
python -m pip install 'selenium>=4.20,<5'
python scripts/odds_collector.py
```

Пока доступность страницы букмекера с IP GitHub Actions не доказана. Точный источник сбоя следует определить по следующему **новому** запуску и его артефакту.
