# Публикация результата задачи в BKliz

Этот блок добавляется к выбранной задаче без изменения её исходного назначения, расписания и правил отбора. Не создавай дополнительные задачи. Репозиторий публичный: публикуй только спортивный обзор, исключая персональные сведения, историю чата, суммы личных средств и секреты.

1. После анализа сформируй JSON по формату ниже. Не выдумывай коэффициенты, события и время проверки. Недоступные коэффициенты и даты начала обозначай null; отсутствие данных объясняй в summary или analysis. Оценки отделяй от подтверждённых фактов. Не добавляй команды ставить и обещания доходности.
2. Репозиторий: StLisovafk13/BKliz, ветка main. Прочитай data/latest.json и TASK_INSTRUCTIONS.md. Для обновления файла используй его актуальный blob SHA. Если tools для фоновой записи недоступны, сообщи об ошибке доставки и не утверждай, что сайт обновлён.
3. Установи generated_at в фактическое время подготовки с часовым поясом. run_id — стабильный идентификатор текущего запуска в нижнем регистре, только латинские буквы, цифры и дефисы; при повторной попытке не меняй его.
4. Создай data/reports/YYYYMMDDTHHMMSSZ-<run_id>.json, где время в имени переведено в UTC. Если файл существует, прочитай и проверь совпадение; не перезаписывай другой отчёт. При конфликте остановись и сообщи об ошибке. Содержимое архива и latest.json должно совпадать. Более старый запуск не должен заменять более новый latest.json.
5. Обнови data/latest.json. Не меняй код, workflow и прошлые отчёты. data/index.json автоматически строится при публикации; не обновляй его вручную. Числа записывай как JSON-числа, не как строки. ID события должен оставаться стабильным между обновлениями.
6. Прочитай latest.json обратно и проверь run_id и содержимое. Отдельно сообщай «записано в GitHub» и «опубликовано на сайте»: публикацию подтверждай только успешным результатом workflow, если он доступен. При сбое сделай не более одной повторной попытки с тем же run_id. Если изменений нет, не создавай новый отчёт без необходимости, соблюдая исходные правила уведомлений задачи.

## Формат (схематический пример, не реальные события)

```json
{
  "schema_version": 1,
  "run_id": "unique-run-id",
  "generated_at": "2026-10-15T20:00:00+05:00",
  "title": "Обзор матчей",
  "summary": "Источники, ограничения и итог анализа.",
  "events": [
    {
      "id": "stable-event-market-id",
      "event": "Команда А — Команда Б",
      "sport": "Футбол",
      "competition": "Название турнира или НЕТ ДАННЫХ",
      "start_at": null,
      "market": "Точный рынок или НЕТ ДАННЫХ",
      "odds": null,
      "status": "Нет данных",
      "analysis": "Подтверждённые факты, затем аналитический вывод и ограничения.",
      "source_name": null,
      "source_url": null,
      "checked_at": "2026-10-15T20:00:00+05:00"
    }
  ]
}
```

Допустимые статусы: Ожидается, Идёт, Завершён, Перенесён, Отменён, Нет данных. checked_at — время фактической проверки, даже если источник оказался недоступен. Коэффициент допускается только с названием и прямой ссылкой источника. Для отчёта без подходящих событий используй events: [] и укажи причину в summary.
