# Публикация трёх задач в BKliz

Репозиторий: StLisovafk13/BKliz, ветка main. Сайт читает три независимых файла; не записывай общий data/latest.json.

| Задача | feed_id | Файл |
| --- | --- | --- |
| Спортивный аналитик — единый цикл | cycle | data/feeds/cycle.json |
| Ежедневный обзор матчей | overview | data/feeds/overview.json |
| Сигналы по ординарам | signals | data/feeds/signals.json |

1. Прочитай этот контракт и свой файл. Не меняй чужие файлы, код, workflow, расписание и предыдущие отчёты. Веди историю отдельно для своей задачи. Сохраняй правила анализа и уведомлений исходной задачи.
2. Каждый новый отчёт — полный снимок своих текущих событий, не только изменившихся строк. Если условия отбора не выполнены, не выдумывай сигнал: events=[] и пояснение в summary. Наблюдение без подтверждённой цены обозначай явно. Ожидающие отчёта файлы и report_kind=bootstrap не являются результатами фонового запуска.
3. JSON отчёта: schema_version=1, feed_id, task_name, report_kind="task", run_id, generated_at, title, summary, events. generated_at — фактическое ISO8601-время с часовым поясом. run_id — уникальный стабильный идентификатор запуска с префиксом feed_id, только строчные латинские буквы, цифры и дефисы. При повторной попытке его не меняй. summary содержит полный публичный отчёт, ограничения и выводы.
4. Каждая строка events: id (стабильный ID события и рынка), event, sport, competition, start_at (ISO8601 с поясом либо null), market, odds (число >1 либо null), status, analysis, source_name (строка либо null), source_url (http/https-ссылка либо null), checked_at (фактическое ISO8601-время проверки). Необязательное calendar_date — дата в исходном календаре для случая неизвестного точного времени. Допустимые статусы: Ожидается, Идёт, Завершён, Перенесён, Отменён, Нет данных.
5. Для коэффициента обязательны название источника и прямая ссылка конкретного рынка. Отсутствующие цены — null. Не подменяй K0 текущей ценой: исходные и новые значения с временем, версии, расчёты и причины изменений сохраняй в analysis/summary. Не подтверждённый текущий статус — Нет данных.
6. Сначала создай неизменяемый data/reports/YYYYMMDDTHHMMSSZ-<run_id>.json (время UTC), затем обнови только свой data/feeds/<feed_id>.json тем же JSON. Прочитай текущий файл и используй актуальный blob SHA. Не перезаписывай более свежий отчёт старым. Если архив уже существует, проверь совпадение; при конфликте остановись. Не редактируй data/index.json, он собирается автоматически.
7. Прочитай свой файл обратно и проверь run_id и содержимое. При сбое одна повторная попытка с тем же run_id и именем. Недоступный инструмент или отказ доступа — ошибка доставки, а не успех. Успешная запись в GitHub не подтверждает публикацию сайта; её можно подтверждать только по успешному GitHub Actions.
8. При первом самостоятельном запуске сохрани честный отчёт даже при events=[]; не выдавай его за сигнал. Далее публикуй при содержательных изменениях и по исходным правилам ежедневного обзора. Не отправляй пустые уведомления, если исходная задача их запрещает. Не создавай дополнительные автоматизации или наборы.
9. Публичные файлы содержат только спортивную аналитику. Исключи персональные сведения, историю чата, секреты и реальные личные средства. Расчётные суммы допускаются только с явной пометкой «условная модель». Не размещай реальные ставки и не обещай доходность.

## Дата, исходная цена и результат для таблицы
В каждой строке дополнительно передавай event_date (подтверждённая дата YYYY-MM-DD либо null; не дата обсуждения), original_odds (исходный K0, число либо null), score (подтверждённый финальный счёт либо null), winner (победитель/ничья либо null), regulation_score (счёт за основное время при ОТ/буллитах либо null), forecast_result (✅ Сбылся / ❌ Не сбылся / ↩ Возврат либо null). Не подменяй K0 текущим odds. Не вычисляй исход ставки из окончательного счёта с ОТ, если рынок на 60 минут. При отсутствии точного рынка или результата оставляй null. Не называй прежнее сообщение ассистента независимым подтверждением.


## Сравнение коэффициентов 11 БК (добавлено по запросу пользователя)
Искать события и точные рынки по порядку: Лига Ставок, PARI, Winline, BetBoom, Фонбет, БЕТСИТИ, Марафонбет, Олимпбет, Леон, Балтбет, 1win. Не включать другие международные БК. Учитывать территориальные ограничения и лицензии; не обходить блокировки. Список источников не означает, что их котировки доступны. На каждом цикле отмечать реально проверенные и недоступные источники; не заявлять проверку всех 11 без фактической проверки.

Для каждого события разрешено необязательное поле bookmaker_odds — массив объектов {bookmaker, market, odds, source_url, checked_at}. Записывать туда только действительно проверенные цены: конкретный матч, дата, точный рынок/исход, прямая ссылка, фактическое ISO-время проверки. Отсутствующие цены не выдумывать. Сопоставлять только идентичные рынки (включая основное время/ОТ, фору и тотал). Не использовать старые цены как актуальные. Поля основной схемы events сохраняются без изменений. На сайте сравнение отображает проверенные цены по всем 11 источникам и ссылку на каждый подтверждённый рынок; неподтверждённые — «Не подтверждён». 1win остаётся отдельным активным источником.

Из активных списков и сравнения исключены: 1xBet — доступ запрещён; 1xСтавка — прекращена букмекерская деятельность, линии нет. Не проверять их в новых циклах и не включать их цены в активное сравнение. Исторические отчёты и ранее сохранённые цены не изменять.

## Коэффициенты при подтверждённом результате
При подтверждении результата сохраняй original_odds (K0), price_history и все ранее зафиксированные источники котировок. Не обнуляй и не подменяй K0 новой ценой; для наблюдения с original_odds=null не устанавливай K0 задним числом.
При первом подтверждении результата добавь result_price — неизменяемый снимок последней проверенной цены выбранного рынка ДО начала события:
{"odds":2.33,"market":"точный рынок из events.market","source_name":"название БК","source_url":"прямая ссылка рынка","checked_at":"ISO8601-время проверки котировки с поясом"}.
Бери снимок из проверенной price_history того же события и точного рынка; checked_at должен быть раньше start_at. Для записи истории без market допустима только история внутри того же стабильного ID события/рынка. Сохраняй реальную дату проверки цены, не заменяй её датой проверки результата. При равном времени разных БК сохраняй ранее выбранную запись, не выбирай задним числом максимальную цену.
После появления result_price не меняй его при повторной проверке результата. Если проверенная цена, её источник, время или предматчевый статус не установлены, result_price=null; отсутствующие значения не выдумывай. price_history сохраняй даже при неполных данных.
Цена result_price является архивной, не актуальной линией и не подтверждением размещения ставки. odds может оставаться null после закрытия линии. Источник результата храни отдельно в result_source_url и result_checked_at, не стирай источник сохранённой цены.
Правило применяется при формировании НОВЫХ отчётов до архивирования. Не редактируй старые архивы. На сайте для завершённых событий показываются K0, если он был, и отдельно архивная цена result_price; при отсутствии снимка допустим показ проверенной предматчевой цены из price_history с той же маркировкой.

## Краткое обоснование под событием
Для каждого события в НОВОМ отчёте передавай selection_reason: одно-два понятных предложения (до 260 символов), почему рассматривается именно этот матч и выбранный рынок. Используй только проверенные спортивные основания: форма, состав, стиль игры, нагрузка, мотивация, статистика. Не подменяй причину техническим журналом проверки, движением цены, итоговым счётом после матча или выдуманной уверенностью. Если основания не установлены, укажи это прямо.
При необходимости добавляй risk_note (короткий главный риск, до 140 символов) и selection_sources: массив {name,url} со ссылками на источники обоснования. Источник котировки и источник результата сохраняй по действующим правилам; не стирай K0, price_history и result_price.
Сайт показывает обоснование и источники под каждой записью. Сравнительная сетка 11 БК в интерфейсе убрана; сравнение источников в процессе проверки и сохранённые bookmaker_odds не нужно удалять. Старые архивы не редактировать.
